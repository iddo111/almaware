### 7א. שובר — receipt

כל סוכן שמשנה **מצב חי** (עוצר שירות, תופס נעילה, כותב PID, משתיק משהו)
חייב שהקובץ שהוא משאיר **יהיה** השובר. לא קובץ נפרד — הסימן עצמו.

הקובץ הוא JSON ובו ארבעה שדות חובה:

| שדה | מה |
|---|---|
| `who` | שם הסוכן — **אותו שם** שאתה משתמש בו ב-`ramlink post` |
| `why` | שורה אחת בשפת בני אדם: למה המצב הזה קיים |
| `at` | ISO-8601 עם אזור זמן |
| `restore` | **הפקודה המדויקת** שמבטלת את זה |

### 7ב. מצב שמשתיק — חייב תפוגה

סימן ש**מכבה משהו שעידו משתמש בו** (מיקרופון, שירות, חלון) מסומן `"disables": true`
ואז `expires` הוא **חובה**, ולכל היותר **12 שעות**. אין מצב-כיבוי פתוח.
תוקף שעבר = הסימן לא תקף, והתוכנה שקוראת אותו חייבת **לצעוק**, לא לציית בשקט.

> 🪟 סימן כיבוי בלי תפוגה הוא חלון שבור. הוא ישרוד את הסוכן שכתב אותו — זה בדיוק מה שקרה.

### 7ג. מי שסיים — מנקה

סוכן שסיים או נהרג מוחק מה שהוא הציב. מה שהוא **לא** הצליח למחוק,
התפוגה תופסת במקומו. `expires` הוא הניקוי שעובד גם כשנהרגת.

### 7ד. תהליך חי הוא השובר של עצמו

`.pid`/`.lock` שמצביע על תהליך **חי** — תקין. רואים אותו, שמו ידוע, אפשר להרוג אותו.
רק כשהתהליך מת הקובץ חייב להסביר את עצמו, כי אז כבר אין מי שיסביר.

### הכלים — זה נבדק מכנית, לא בכוונות טובות

```bash
# לכתוב סימן תקין (מסרב לכיבוי בלי תפוגה, ומעל 12 שעות)
python D:\CLAUDE\RAMCHAT\receipts.py write <path> --who <שמך> \
       --why "<סיבה>" --restore "<פקודה שמחזירה>" [--disables --expires-in 4h] [--pid <pid>]

# לבדוק את כל העץ. exit 0 = נקי, exit 1 = יש הפרה
python D:\CLAUDE\RAMCHAT\receipts.py check --root D:\CLAUDE
```

`check` נופל על: קובץ לא-מיוחס (הצורה של KESHEV), שדה חובה חסר, תפוגה שעברה,
כיבוי בלי תפוגה, ו-`.pid`/`.lock` שהתהליך שלו מת.
**כל RUN-*.cmd של שירות שעידו נוגע בו צריך להריץ `check` לפני שהוא עולה.**

הדוגמה הטובה שכבר קיימת בשטח — `eran4:~/darwish-midi/PAUSED-20260824.txt`:
