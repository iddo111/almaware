## The mechanism

- `server.py` runs under **pythonw.exe** (windowless), launched at logon by
  `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\ALMAWARE-Ant-Dashboard.vbs`.
- Every `REFRESH_SECONDS = 120` it calls `subprocess.run(["ssh", ..., node, "python3 -"])`
  for **eran1-eran4 in 4 parallel threads**.
- Because the parent has **no console** and the call passed **no `creationflags`**, Windows
  allocated a brand-new console for each ssh, so the default terminal host (Windows Terminal)
  opened **4 visible windows at once**, which closed a few seconds later when ssh finished.
- Same bug class as the July 22 incident (`COCKPIT (collector).lnk.pre-popup-fix-20260722`):
  the collector was fixed then; the ant-dashboard (written 2026-08-06) reintroduced it.

## The fix (applied 2026-08-08 01:20, survives reboot)

`C:\Users\<user>\ant-dashboard\server.py`:

    CREATE_NO_WINDOW = getattr(subprocess, "CREATE_NO_WINDOW", 0)   # new constant
    ...
    subprocess.run([...ssh...], input=script, capture_output=True, timeout=60,
                   creationflags=CREATE_NO_WINDOW)                  # added flag

- Old process (PID 17212) stopped; relaunched via its own Startup VBS -> new PID 18920.
- Persistence: the Startup VBS re-runs the **patched file** at every logon. Nothing was
  disabled or deleted; the dashboard itself is Iddo's and stays fully functional.
